# Privacy

Embercue v0.1 stores its library locally in Application Support. It has no Embercue-operated account, sync service, analytics, telemetry, crash upload, AI/model call, licensing flow, update check, or other network client.

The application does not programmatically read, monitor, or poll the general clipboard while it launches, shows, hides, searches, or changes views. `Keep Clipboard` reads plain text only after you select that command. **Enable Double-Shift Capture…** is the single default-off consent: it reads an accessible selection directly, or when the focused app exposes none, sends one Command-C to the captured frontmost non-Embercue PID and makes a short bounded wait. Every check requires that same PID to remain frontmost, and it reads only a nonblank plain-text value when the pasteboard count is exactly one greater than its pre-copy snapshot. Focus loss, a count jump, timeout, blank result, disabled mode, or stale callback never reads or captures the prior clipboard value. It never activates another app, pastes, submits, clears, restores, or monitors the clipboard. `Copy` and `Copy & Return` write plain text only after you select them. These limits do not restrict ordinary macOS text editing or user-initiated paste shortcuts. The macOS general pasteboard may participate in Universal Clipboard after an explicit copy; Embercue does not control that system behavior.

Attachments selected through drag/drop or the paperclip are copied into Embercue's private Application Support directory. Embercue stores only the managed relative reference, filename, byte count, and optional local type identifier; it does not retain the source path.

The previous application used by `Copy & Return` stays only in memory and is not saved, exported, or logged. Embercue does not request Accessibility at launch. Only after choosing **Enable Double-Shift Capture** does it install paired local and global monitors limited to modifier-flag transitions. Only Shift presses count toward the gesture; Command, Option, Control, and Fn cancel it. An uninterrupted double Shift synchronously reads the current selection through standard Accessibility attributes; each focused candidate's direct text, selected range, and full value are tried before a bounded ancestor. On the exact unavailable result, it is the only synthetic input and sends Command-C once to a guarded frontmost non-Embercue target. Empty selection, permission, monitor, revoked, stopped, disabled, and unknown paths do not read or send input. Embercue never reads ordinary key presses or text, pastes, submits to another app, or requests Automation, Screen Recording, Full Disk Access, or other protected permissions.
