# Embercue architecture

## Modules

`EmbercueCore` owns the versioned `LibraryDocument`, item validation, semantic state changes, and repository boundary. Schema v3 stores unique ordered `LibrarySection`s, item placement, and bounded managed `LibraryAttachment` references. `LibrarySchemaCodec` decodes literal v1/v2 separately without writing on load. `AttachmentStore` accepts only regular, non-symlink source files up to 20 MiB, copies them to a 0700 managed `attachments/` directory with 0600 files, and exposes only validated relative references. A composer mutation imports all pending attachments first, saves the candidate document, and deletes only that operation's imported files if saving fails. `JSONLibraryRepository` preserves exact v1/v2 bytes in owner-only migration snapshots before the first v3 mutation, while backup recovery restores validated raw bytes rather than re-encoding legacy data. `LibraryEngine` is main-actor confined and publishes candidate changes only after a repository save succeeds.

`EmbercueMac` owns AppKit/SwiftUI integration. `SystemClipboard` is the sole pasteboard adapter. `ForegroundApplicationTracker` retains only an in-memory `NSRunningApplication` reference. `CarbonGlobalHotKey` registers exactly Control-Command-J with Carbon; it does not observe arbitrary key events. `WorkbenchModel` projects active cards through ordered document sections and keeps search, selection, expansion, completion echo, capture target, draft, and editor state transient. Its semantic router is the only path for Copy, Copy as List, Mark as Done, edit, merge, and move. `SafeMarkdownText` parses caller-owned strings with pinned `swift-markdown` 0.8.0 and renders only local text/strong/emphasis/code/strike runs; it discards link destinations, image sources, HTML, and attachments. `PanelController` hosts a key-capable, resizable 364×640 floating rail at the right edge of the active display with a 64 pt default inset and vertical centering. Its pure placement seam preserves requested size and dynamic small-display containment. It has `hidesOnDeactivate = false`, intercepts close to `orderOut`, and is retained after closing. The app delegate rejects last-window termination, so the template menu-bar item and hot key remain available until explicit Quit. A QA-only native appearance override is accepted only when an isolated `EMBERCUE_DATA_DIRECTORY` is present.

## State and privacy boundary

```
SwiftUI intent -> WorkbenchModel -> LibraryEngine -> JSON repository -> local JSON
explicit copy -> SystemClipboard -> macOS general pasteboard
copy & return -> successful selected-card copy -> panel hide -> in-memory previous application activation
explicit double-Shift capture consent -> Accessibility prompt -> local + global modifier-flag monitors -> double-Shift gesture -> standard AX selection per focused candidate then bounded ancestor -> exact unavailable: one guarded Command-C -> bounded changed-pasteboard read -> WorkbenchModel
```

No view manipulates JSON, clipboard contents, Carbon registration, or another application directly. A typed draft remains in the model after a failed save. Copy is deliberately not a state transition; only `Done`, `Archive`, and `Restore` modify item state. Copy as List completes only after a combined pasteboard write succeeds. The optional paired local/global monitors start only after the one explicit `doubleShiftCaptureEnabled` opt-in and Accessibility trust; a legacy selection-only preference is ignored. On exact AX unavailability, `FrontmostSelectionCopier` rejects Embercue or an absent/terminated target, sends exactly one Command-C without activating any application, and makes at most six short operation-local checks. Each check requires the original target PID still be frontmost and accepts only a pasteboard count exactly one higher than the pre-copy snapshot; focus loss, a count jump, timeout, blank text, disabled setting, or stale callback cannot read the prior clipboard. The monitors inspect modifier `flagsChanged` state, count only Shift presses toward the gesture, synchronously enter the main actor, retain local events unchanged, and are generation-scoped so callbacks from a stopped or replaced registration are inert. Capture and copy completions have their own generation and are cancelled on stop, disable, or a later gesture. Command, Option, Control, Fn, unchanged Shift transitions, and clock rollback reset the gesture. Each focused AX candidate resolves direct text, then selected range, then full value before any ancestor is tried. Empty selection, permission, monitor, revoked, stopped, and unknown paths never read the clipboard or synthesize input. Search and the History page are transient presentation state; closing or hiding the rail does not clear them.

Schema v1 contains `schemaVersion`, `revision`, and item identifiers, kinds, states, timestamps, and text. Schema v2 adds sections and item placement. Settings and selection are intentionally not retained in the content document. There is no source-app history, clipboard history, payload logging, network transport, or account data.

For isolated smoke tests, `EMBERCUE_DATA_DIRECTORY` can name an absolute data directory. Embercue validates it as a non-symlink directory and does not treat `HOME` as a storage-isolation switch.

## Distribution boundary

The package script emits an ad-hoc-signed local `.app`. It is not a Developer ID, hardened-runtime, notarized, stapled, or Gatekeeper-validated release. Public branding and distribution remain human release gates.
